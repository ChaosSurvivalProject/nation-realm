# 架构

## 目标基线
200 在线玩家 / 20 国家 / 最多 1600 NPC / 50 万已探索区块 / 60 秒地图刷新周期。
国家任务主线程影响目标 ≤ 50ms/分钟预算（不是全部业务只有 50ms）。

## 模块边界
```
客户端 (Fabric, 客户端侧)  <--版本化协议-->  服务端 (Purpur 插件)
                                                   |
                                              nation-core (领域)
                                                   |
                                            仓储接口 -> MySQL 8
                                                   |
                                            AI 工作器 (独立进程)
```

- `common-protocol`：纯 Java，只放可共享类型与编解码；无 MC / JDBC。
- `nation-core`：领域逻辑可在无 MC 环境测试；仓储接口隔离持久化。
- `purpur-plugin`：薄适配层——事件入口、命令、调度、结果应用；DB/AI/压缩/路径在异步线程或独立进程。
- `fabric-client`：客户端仅可视化与交互，无规则决定权；独立 Loom 构建。
- `ai-worker`：独立进程，模型只返回意图 JSON，服务端状态机验证后执行。

## 线程模型
- 主线程：事件入口、有限批量结果应用；使用批次 + 截止时间 + 继续游标，避免单次大任务卡服。
- 异步：DB 查询、AI 调用、压缩、路径计算。
- 区块探索：玩家移动入队（主线程，仅去重）→ 异步批量落库。

## 数据一致性
- 从第一天写入 `server_id`、`version`、`last_write_server`、租约、幂等键、事件序号。
- 首版跨服策略：国家业务集中在“国家服”，其他服通过消息代理调用，避免多后端同时写同一国家。
- 缓存快照 + 增量版本号 + 明确失效规则；MySQL 仍是事实源。

## 版本边界
- Purpur 1.21.1（固定构建号封测，升级前跑兼容测试）；Java 21。
- Fabric 1.21.1 + Yarn `1.21.1+build.3` + Fabric Loader 0.16+。
- 协议主版本 1；主版本不兼容拒绝启用高级界面，次版本尽力兼容。

## 可观测性
指标：tick 耗时、阶段耗时、SQL P50/P95/P99、连接池、协议体积、丢包、队列积压、AI 成本、NPC 决策延迟、失败率。
结构化日志带 requestId / 玩家 / 国家 / serverId / 实体 ID；禁止泄露密钥与敏感信息。
如用 `--add-modules jdk.management` 暴露管理指标，须在启动脚本记录，不依赖神秘默认。
