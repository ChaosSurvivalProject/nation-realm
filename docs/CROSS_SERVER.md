# 跨服（阶段7 骨架）

## 目标架构
Velocity 前端 + 多个 Purpur 后端；共享 MySQL；Redis 可选承担跨服消息、在线状态、短期缓存。MySQL 仍是事实源；无 Redis 的单服模式继续工作。

## 首版策略
- 国家业务集中在指定“国家服”；其他服通过消息代理调用，避免多后端同时修改同一国家。
- Velocity 子模块只实现连接路由、玩家服务器定位、消息信封、切服状态协议。

## 一致性机制
- Outbox 发布（`outbox_events.seq`）、消费幂等（`idempotency_keys`）、实体版本、服务器租约。
- 切服：先保存 → 确认 → 再迁移，防止旧服迟写覆盖新服。
- 延迟消息、死信队列、消费者重复与代理重发都按幂等处理。

## 故障演练（可重复执行）
同玩家双服登录、旧服迟写、代理重发、消费者重复、数据库短暂不可用、事件顺序异常。
验收：相同事件处理两次只生效一次；切服不丢未保存操作；旧服无法覆盖更新版本；故障可恢复或管理员明确处置。

## 当前状态
表结构与领域基础（幂等/版本/Outbox）已备；Velocity 子模块与多服集成演练为后续工作，未标为完成。
